# Проекты аналитической академии

Учебные проекты на синтетической банковской базе PostgreSQL (`academy_db`).
Каждый — полный цикл: подключение к базе, сборка признаков с нуля, модель,
экономика решения и защита результата.

> **Данные синтетические.** Подключение требует собственных учётных данных.
> В репозитории их нет: ноутбуки берут пароль из переменной окружения `DB_PASS`,
> а при её отсутствии запрашивают интерактивно и в файл не сохраняют.

---

## Прогноз оттока — `churn/`

Клиент считается ушедшим, если не совершил ни одной успешной операции в окне
60 дней, начинающемся **через 30 дней** после даты снимка. Лаг между признаками
и окном исхода — время на скоринг, решение и контакт.

**Качество заявлено диапазоном, а не одной цифрой: Gini 0,62** на спокойном
периоде и **0,52** на периоде с тарифной реформой. Основание: внутри одного
периода разные способы измерения расходятся на 0,006, между периодами — на 0,10.
Неустойчива не модель, а период.

**Таргет не сводится к давности последней операции** — три проверки:
45% ушедших были активны внутри лага; медиана молчания 8 дней против 4
у оставшихся; снятие всех признаков давности стоит 0,001 Gini.

**Эффект удержания на этих данных не идентифицируется** — и это разобрано
как результат, а не как неудача. Контакт назначается по исходу: медиана
молчания у контактированных 34 дня против 4 в контроле, AUC модели склонности
0,940, эффективный размер выборки 23,6 при 204 наблюдениях. Вывод для бизнеса:
программа запускается слишком поздно и работает как возврат, а называется
удержанием.

Дополнительно: анализ выживаемости с корректным цензурированием (наивная версия
давала 100% событий и бессмысленные коэффициенты Кокса), экономика удержания
с параметрами, выведенными снизу вверх под местный рынок.

## Типология клиентской базы — `segmentation/`

Задача без таргета: построить типологию клиентов для перестройки тарифной линейки.

**Пять типов.** Число защищено тремя независимыми метриками — максимум силуэта
(0,306), минимум Дэвиса-Болдина (1,236) и перелом инерции, все при k = 5.

**Устойчивость измерена числом:** средний ARI 0,974 по десяти проверкам —
другой random_state, половина выборки, окно без последнего месяца, изменённый
набор признаков.

**Сравнение с квартилями оборота:** типология объясняет структуру поведения
втрое лучше (0,552 против 0,231) при ARI между разбиениями 0,216, то есть
не переоткрывает оборот дорогим способом.

**Экономика тарифной реформы: +5,0% к выручке** при неизменном поведении.
Расчёт разделён на механический слой (считается из данных без допущений)
и поведенческий (остаётся гипотезой до эксперимента).

Отдельно разобрана ловушка задания: число клиентов в помесячных таблицах
растёт с 15 013 до 20 000 — это накопление регистраций, и признаки за все
24 месяца дали бы типологию по дате прихода, а не по поведению.

## Как запустить

```bash
pip install pandas numpy scikit-learn matplotlib scipy sqlalchemy psycopg2-binary
```

Пароль к базе задаётся переменной окружения:

```powershell
# Windows PowerShell
$env:DB_PASS = 'ваш_пароль'
```

```bash
# Linux / macOS
export DB_PASS='ваш_пароль'
```

Если переменная не задана, ноутбук спросит пароль при запуске первой ячейки
и никуда его не запишет.

## Структура

```
.
├── churn/           отток: ноутбук и презентация защиты
├── segmentation/    типология: ноутбук и презентация защиты
├── .gitignore
└── scan_secrets.py  проверка на попадание паролей перед коммитом
```

Перед каждым коммитом:

```bash
python scan_secrets.py
```
